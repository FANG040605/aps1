# 接口契约（前后端对齐用，写在前、写在先）

> 六个接口，前端不解析 xlsx，只画 JSON。所有错误都回 `{"detail": "中文提示"}`，前端直接显示。
>
> 分三组：**排产**（1、2、3）、**产线基线**（4）、**设备事件**（5、6）。
> 设备和工艺路线配一次就存进基线，之后排产只需要订单表——所以 `POST /api/plan`
> 接受"只有订单表"的文件，缺的两张从基线补。

## 0. 约定

| 项 | 约定 |
|---|---|
| 地址 | `http://127.0.0.1:8765`（可用 `--port` 改） |
| 编码 | 请求/响应 UTF-8；响应 `Content-Type: application/json; charset=utf-8` |
| 连通性自检 | `GET /api/ping` → `{"ok": true, "app": "aps-scheduler"}`；启动器重复双击时用它判断"是我自己还是别的程序占了端口" |
| 缓存 | 接口响应带 `Cache-Control: no-store`，刷新必定拿新数据 |
| 错误 | `400` 用户能看懂的问题（文件不对、三张表没找齐、空表）；`404` 任务过期；`500` 兜底，只回异常类型不回堆栈 |
| 数据留存 | 只保留最近 5 次任务，更早的目录自动删除 |

## 1. `POST /api/plan` — 上传订单（或完整台账）并生成

**请求**：`multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | 文件 | 是 | `.xlsx`，≤12 MB，须含「订单 / 设备 / 工艺路线」三张表 |
| `start_date` | 文本 | 否 | `2026-11-09`；留空取「现在之后第一个可开工时刻」（不跳下周一）；早于当前时刻会被夹到当前时刻并记一条体检 |
| `allow_switch` | 文本 | 否 | `true` / `false`，默认 `true`（允许同组替换机台） |

**成功 `200`**（节选，字段全量见下）

```json
{
  "job_id": "20261104-144229-348b",
  "params": "起始 2026-11-05 15:29 ｜ 每班 8h，班制 2 班、3 班 ｜ 周日不排 … ｜ 目标 迟到单数→迟到天数→总完工 …",
  "rule": "SPT+局部交换(39)",
  "start": "2026-11-05 15:29",
  "finish": "2026-11-20 17:29",
  "metrics": [
    {"k": "读入订单", "v": 14, "u": "条", "s": "排产 14 单"},
    {"k": "工序任务", "v": 51, "u": "道", "s": "分钟/件 × 数量"},
    {"k": "总完工", "v": "11-20", "u": "17:29", "s": "规则 SPT+局部交换(39) 最优"},
    {"k": "校验违反", "v": 0, "u": "项", "s": "五条硬约束", "tone": "ok"},
    {"k": "迟到订单", "v": 0, "u": "单", "s": "另 2 单交期物理不可能", "tone": "bad"},
    {"k": "数据问题", "v": 23, "u": "条", "s": "11 类，5 条待确认", "tone": "warn"}
  ],
  "schedule": [
    {"machine": "CNC-01", "order": "HD-2026-111", "op": "铣", "qty": 20,
     "start": "11-10 13:40", "end": "11-11 17:40", "minutes": 1200, "product": "阀体A"}
  ],
  "gantt": {
    "days": [{"label": "11-09", "left": 0.0}],
    "machines": [{"name": "CNC-01", "load": 147,
                  "bars": [{"order": "HD-2026-111", "op": "铣", "qty": 20, "product": "阀体A",
                            "left": 5.2, "width": 8.1, "tip": "HD-2026-111 · 铣 · 20件 · …"}]}]
  },
  "risks": [
    {"order": "HD-2026-102", "due": "2026-11-12", "lb": "11-17 19:29", "eta": "11-19 22:20",
     "gap": -7.2, "machine": "GRD-01", "op": "磨", "status": "不可行",
     "note": "独占最快机台、零排队也要 11-17 19:29 才完工，比交期晚 5.1 天——交期本身不成立",
     "infeasible": true}
  ],
  "issues": [{"category": "交期口径", "where": "订单!D7", "symptom": "原文「尽快」不是日期",
              "action": "按口径折算为 2026-11-09", "need_confirm": true}],
  "violations": [],
  "downloads": [{"kind": "schedule", "name": "排单表.xlsx", "url": "/api/download/<job_id>/schedule"}]
}
```

`status` 取值：`不可行`（交期下界已超交期，只能改期/外协）/ `迟到`（排得不好，可优化）/ `临界`（余量<1天）/ `按期` / `需确认`（交期是文字或空白）/ `未排产`（数据不全）。
`lb` 为交期下界（独占最快机台、零排队的最早完工时刻），`infeasible` 等价于 `status == "不可行"`。
`tone` 取值：`ok` / `bad` / `warn`，前端只按它上色，不自己判断规则。

**失败**

| 情况 | 状态码 | `detail` |
|---|---|---|
| 传了 `.txt` / `.csv` | 400 | 这个文件打不开，不是 Excel 台账。当前文件：xxx.txt。请上传 .xlsx… |
| 扩展名对但内容不是 Excel | 400 | 文件内容不像 Excel（可能已损坏或只是改了扩展名）… |
| 缺工作表 | 400 | 缺少工作表：工艺路线；需要「订单 / 设备 / 工艺路线」三张表 |
| 表里没数据 | 400 | 「订单」表里没有读到数据行，请检查是不是空表或表头被删了 |
| 文件 > 12 MB | 400 | 文件超过 12 MB，请确认是不是选错了文件 |
| 其他异常 | 500 | 排产时出错：<异常类型>。请把台账发给我们核对。 |

## 2. `GET /api/result/{job_id}` — 取回结果

返回体与 `POST /api/plan` 成功响应**完全一致**。用于刷新页面后恢复上一次结果。
`404` → `{"detail": "这次结果已经过期，请重新上传台账生成"}`。

## 3. `GET /api/download/{job_id}/{kind}` — 下载产物

| `kind` | 文件名 |
|---|---|
| `schedule` | 排单表.xlsx |
| `gantt` | 甘特图.html |
| `risk` | 风险清单.md |
| `checkup` | 体检报告.md |

响应头（中文名不乱码的关键）：

```
Content-Disposition: attachment; filename=file.xlsx; filename*=UTF-8''%E6%8E%92%E5%8D%95%E8%A1%A8.xlsx
```

`filename=` 给老浏览器兜底，`filename*=UTF-8''` 才是中文名。文件不存在或任务过期 → `404`。

## 4. `GET /api/profile` / `POST /api/profile` — 产线基线

**读**：`GET /api/profile`，无需参数。

```json
{
  "exists": true,
  "updated": "2026-11-05 16:03",
  "fingerprint": "425a65c57a",
  "summary": "12 台设备（2 台不可用：CNC-03、HT-01）｜5 个产品工艺｜覆盖工序 下料、攻丝、热处理…",
  "machines": [
    {"code": "GRD-01", "ops": ["磨"], "shifts": 2, "status": "在用", "usable": true,
     "down": true, "down_until": "11-09 08:00"}
  ],
  "products": [{"product": "阀体A", "steps": ["下料（SAW-01）20", "铣（CNC）45"], "total": 65}],
  "events": [{"id": "20261105-160637-db0d", "machine": "GRD-01", "kind": "故障",
              "from": "2026-11-05 16:06", "until": "2026-11-09 08:00",
              "note": "主轴异响", "active": true}]
}
```

`exists=false` 时其余字段为空数组/空串，前端据此提示"第一次使用请先传完整台账"。

**写**：`POST /api/profile`，`multipart/form-data` 上传**完整台账**（订单 + 设备 + 工艺路线），
把设备与工艺路线存成 `data/产线基线.xlsx`。返回结构与上面一致。覆盖前自动留一份
`产线基线.上次.xlsx`。缺表 → `400` + 中文提示。

## 5. `POST /api/machine` — 登记设备故障

```json
{"machine": "GRD-01", "kind": "故障", "until": "2026-11-09T08:00", "note": "主轴异响"}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `machine` | 文本 | 是 | 机台编号，必须与设备表一致 |
| `kind` | 文本 | 否 | `故障`（默认）/ `保养` / `停机` |
| `until` | 文本 | 否 | 预计恢复时间；**留空 = 归期未定**，按整个计划期（120 天）不可用算 |
| `note` | 文本 | 否 | 原因，写进事件流水 |

响应：`{"ok": true, "event": {...}, "profile": {…同 GET /api/profile…}}`。
登记后前端刷新机台红点，并在已选文件的情况下自动重排。

## 6. `POST /api/machine/recover` / `undo` — 恢复与撤销

**恢复**：`{"machine": "GRD-01"}` → 把该机台所有未结束的停机截断到此刻，
响应 `{"ok": true, "closed": 1, "profile": {…}}`。
调停还没开始的登记（提前登记"明天故障"、今天就修好了）会**整条作废删除**，
避免留下"起点晚于终点"的倒置区间。

**撤销**：`{"id": "20261105-160637-db0d"}` → 删掉这条登记错的记录。

## 7. 自测开关（仅供演示与截图）

| 地址 | 效果 |
|---|---|
| `/?job=<job_id>` | 直接打开某次结果 |
| `/?job=<job_id>#gantt` | 直接打开某个页签（`schedule` / `gantt` / `risk` / `checkup`） |
| `/#demo-error` | 显示"传错文件"的错误态，用于截图与课堂演示，不产生任何请求 |
