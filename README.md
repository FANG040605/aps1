# 宏达精密 · 本地排产助手（简化版 APS）

一句话：把计划员的 Excel 台账变成一张车间照着能干的周排单表，并告诉他哪几单要赶不上。

车间里天天变的只有订单，设备和工艺路线基本不动。所以**设备与工艺路线配一次就够了**，
之后每天只交一张订单表。

## 一、做什么

给常州宏达精密的计划员用。拖入订单表 → 点一下 → 出五件产物：

1. 周排单表（可打印：机台 / 单号 / 工序 / 数量 / 开工 / 完工 / 工时）
2. 甘特图（单文件 HTML，断网也能双击打开）
3. 交期风险清单（单号 / 交期 / 交期下界 / 预计完工 / 差额 / 卡在哪台机）
4. 数据体检报告（脏数据分类、处理方式、需客户确认项）
5. 待补充订单（这次没排上的单：卡在哪、该怎么改）

纯本地运行、不联网、不写数据库，客户数据不出本机。

**做**：作业车间排产、按「迟到单数 → 迟到天数 → 总完工」取最优、交期可行性下界、同组机台任选与停机替代、设备故障重排、数据不全就退回、单文件本地运行。
**不做**：柔性工艺路线优化、多目标权衡、换型时间与人员资质、插单自动重排、多用户与服务器部署。

## 一之二、三种用法（选一种，不用全用）

| 场景 | 交什么 | 工具做什么 |
|---|---|---|
| **第一次配置**（或买了新设备、工艺改了） | 完整台账（订单 + 设备 + 工艺路线） | 排一次产，同时把设备与工艺路线存成**产线基线** `data/产线基线.xlsx` |
| **日常排产**（每天/每周） | **只交订单表** | 设备与工艺从基线自动补上，直接排 |
| **机台坏了/保养** | 订单表 + 在网页上点一下那台机 | 停机时段叠加到基线上重排，不写进设备表 |

两条硬规矩：

- 基线文件就是一份普通 xlsx，计划员随时能双击打开改（改完下次排产自动生效，不用点"保存配置"）。
  每次覆盖前会留一份 `产线基线.上次.xlsx`，传错台账也拿得回来。
- **设备状态不要直接改设备表的"状态"列**。那是长期属性（在用/外协/闲置）；
  "周三主轴坏了"是临时事件，改状态列修好之后容易忘了改回来，那台机器就永远排不上活。


## 二、怎么跑

### 环境

| 项 | 版本 | 检查命令 |
|---|---|---|
| Python | 3.10+（已在 3.13.14 与 3.12.0 上实测通过） | `python --version` |
| openpyxl | 3.1.5 | `python -c "import openpyxl; print(openpyxl.__version__)"` |
| Git | 2.x（仅开发需要，运行不需要） | `git --version` |

装依赖（只需这一个第三方库）：

```bash
python -m pip install openpyxl
```

> **装完还是报 `No module named 'openpyxl'`？**
> 说明 `pip` 和 `python` 不是同一个解释器（电脑上装了几套 Python 时很常见）。
> 用带完整路径的写法再装一次，一定对得上：
>
> ```bash
> python -c "import sys; print(sys.executable)"          # 先看运行用的是哪个
> "C:\完整\路径\python.exe" -m pip install openpyxl      # 就往这个里装
> ```
>
> 现在程序启动时也会先自检：缺库会直接给出上面这条带路径的命令（退出码 3），
> 不再抛一屏英文堆栈。


### 台账长什么样（两种放法都行）

一个 `.xlsx`，里面要有三张表：**订单 / 设备 / 工艺路线**。怎么摆随你：

| 放法 | 长什么样 | 说明 |
|---|---|---|
| A. 三个工作表 | `订单`、`设备`、`工艺路线` 各一张 sheet | 客户台账原件就是这样 |
| B. 一个工作表三段 | 三张表在**同一张 sheet** 里上下排开，每段第一行放该段表头，段之间空一两行 | 计划员喜欢放一张表里对着看 |

工作表和表名随便叫（`台账`、`Sheet1`、`订单表` 都行）——工具靠**表头关键字**认表，不靠名字认：

| 表 | 表头至少要有 |
|---|---|
| 订单 | 单号 · 交期 · 产品（三者取二） |
| 设备 | 设备号 / 编号 · 可做工序（取二） |
| 工艺路线 | 产品 · 工序1（取二） |

表头不必在第几行，前面有标题行、下面有"注：…"的注释行都能跳过去。
一段在哪儿结束？下一段表头出现的那一行——所以三段挨在一起也不会串行。
同一份数据，两种放法排出来的结果完全一样（`tests/test_reader.py` 就是这么验的）。


### 命令行跑一次（后端）

```bash
# 日常：只交订单，设备与工艺从产线基线取
python run.py 订单.xlsx --out out

# 第一次（或产线变了）：交完整台账，顺手更新基线
python run.py data/宏达精密_订单台账.xlsx --out out

# 磨床坏了，停到 11-12 08:00，重排
python run.py 订单.xlsx --out out --fault "GRD-01@2026-11-12 08:00@主轴异响"

# 修好了，重排
python run.py 订单.xlsx --out out --recover GRD-01
```

`--fault` 只写机台号表示"归期未定"（按整个计划期停机算）。要临时不用基线、
把三张表当一次性输入跑，加 `--no-profile`。

产物落在 `out/`：

```
out/排单表.xlsx    out/甘特图.html    out/风险清单.md    out/体检报告.md    out/待补充订单.xlsx
```

### 网页版（本地服务，N5 已完成）

**最省事：双击 `启动.bat`**，黑窗口起来后浏览器会自动打开，用完关窗口即可。

或者手打命令：

```bash
python web/app.py --port 8765
# 浏览器打开 http://127.0.0.1:8765
```

网页版走的是同一个 `core/pipeline.py`，所以页面上的数字和命令行完全一致。

页面上从上到下是：**产线状态**（点机台登记故障/恢复，登记完自动重排）→ 上传订单表 →
参数 → 生成 → 五个页签（排单表 / 甘特图 / 风险清单 / 体检报告 / 待补充）。

端口被占用时换一个：`python web/app.py --port 8766`；不想自动开浏览器加 `--no-open`。

接口契约见 `web/接口契约.md`（排产 + 产线基线 + 设备事件，含错误码）。

### 单元测试

```bash
python -m unittest discover -s tests -v
```

> 说明：`run.py` 已可用（N4 完成）；`web/app.py` 在 N5 落地。
> 产物目录 `out/` 已加入 .gitignore——里面是客户数据的衍生结果，不进版本库。

## 三、目录说明

```
aps-scheduler/
├── README.md              本文件：做什么、怎么跑、目录
├── .gitignore             排除缓存 / 产物 / 客户数据（红线）
├── config.py              长期参数：班次、日历、交期口径、工时单位
├── preflight.py           启动自检：缺 openpyxl 时给中文提示（不甩堆栈）
├── run.py                 命令行入口（N4）
├── core/                  后端模块，一个文件一件事
│   ├── reader.py          读台账：三个 sheet 或一个 sheet 三段都行，按表头关键字切段
│   ├── profile.py         产线基线：设备 + 工艺路线存一次，之后只交订单
│   ├── events.py          设备事件：故障/保养/恢复，排产时叠加成停机窗口
│   ├── cleaner.py         洗脏数据 + 逐条记 issues
│   ├── instance.py        订单 → 工序任务（分钟/件 × 数量）
│   ├── solver.py          六套规则并行 + 局部交换，交期优先；交期可行性下界
│   ├── checker.py         五条硬约束，独立于求解器
│   └── report.py          排单表 / 甘特 / 风险 / 体检 / 待补充订单
├── web/                   本地服务与前端
│   ├── app.py             http.server，标准库（不引 Flask）
│   ├── index.html         单页：上传 → 生成 → 四页签 → 下载
│   └── 接口契约.md         3 个 API、错误码、自测开关
├── tests/                 单元测试（≥3 个）
├── docs/
│   ├── 设计说明书.md      N2
│   ├── ui/                N3：三张图 + 交互说明
│   ├── screenshots/       N5：成功态 / 错误态 / 三个页签
│   └── 测试报告.md        N6
├── data/                  客户台账放这里，已 gitignore，绝不进库
└── out/                   程序产物，已 gitignore
```
