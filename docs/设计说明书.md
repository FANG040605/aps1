# 宏达精密 · 本地排产助手 设计说明书

> 版本 v1.0 ｜ 对应节点 N2 ｜ 作者：APS 开发组 ｜ 日期：2026-11-04
> 一页纸原则：说清"做什么、不做什么、凭什么这么定"。技术实现细节见代码与 README。

## 一、用户与场景

| 角色 | 谁 | 在什么情况下用 | 用它干什么 | 关心什么 |
|---|---|---|---|---|
| **计划员（主用户）** | 小李，宏达排产岗，会用 Excel、不懂编程 | 每周一上午，或客户临时插单时 | 把本周订单台账排成每台机的时间表，打印贴墙 | 表要能直接照着干、别撞机、改完能重跑 |
| **老板 / 生产经理** | 张工，管交期承诺 | 客户打电话问"下周能出不" | 打开交期风险清单，看哪几单要晚、卡在哪台机 | 敢不敢答应交期、晚几天、卡在哪 |
| **（非目标用户）IT / 外部顾问** | — | — | 不做多用户、不做部署、不做权限 | 明确不做 |

**场景一句话**：客户一催，小李往 Excel 里插一行，前面的全乱；挤完机床就撞了；交期只能回"尽量"。
工具要解决的就是这一句：**这周每天每台机干什么，哪几单要赶不上。**

## 二、功能清单

### P0 · 必做（5 条，3 周内必须全部跑通）

| 编号 | 功能 | 验收形态 |
|---|---|---|
| P0-1 | **读三个 sheet 并清洗**：处理 8 类以上脏数据，每条记录"类别 / 位置 / 现象 / 处理方式 / 是否需客户确认" | 体检报告里 ≥8 类，≥3 类标"需客户确认" |
| P0-2 | **订单转工序任务**：按工艺路线展开，工时 = 单件分钟 × 数量 | 抽一单手算，分钟数一致 |
| P0-3 | **规则排程 + 独立校验**：FIFO / SPT / MWKR / EDD / EDD+SPT / ATC 各算一遍，按「迟到单数 → 累计迟到天数 → 总完工」取最优，再做插入式局部交换；五条硬约束校验 0 违反 | 校验器输出五项全 0 |
| P0-4 | **出四件产物**：周排单表 xlsx、甘特图 html、风险清单 md、体检报告 md | 四个文件都能打开 |
| P0-5 | **本地网页版**：上传台账 → 生成 → 四个页签 → 下载 | 浏览器里全流程走通，出错有中文提示 |

### P1 · 应做（有余力再做，不做的写进交接说明）

- 参数区：起始日、是否允许换机台、数量空白策略（三项目前写死为默认值）
- 甘特图悬停显示单号 / 工序 / 起止时间
- 体检报告按"处理方式"分组（统一 / 剔除 / 问客户）并可折叠
- 同一份输入重跑结果一致（确定性校验）

### P2 · 可做（本次不做）

- CP-SAT 求解器替代规则排程
- 甘特图导出 PNG、支持 CSV 输入
- 插单预演（新单插进来后哪些单受影响，只预演不自动改排）

> **砍掉的功能及理由**：柔性工艺路线优化（客户没有多路线需求）、换型时间与人员资质（台账里没有这两个字段，硬加等于编数据）、多目标权衡（目标已明确为字典序：迟到单数 → 迟到天数 → 总完工，不再扩成加权多目标）、插单自动重排（业务上还是人工点头，工具只做提示）。

```
                                            │ issues           │ tasks
                                            ▼                  ▼
┌─────────────┐   ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│   交付物     │◀──│   report    │◀──│   checker   │◀──│   solver    │
│ 排单表/甘特/  │   │ 四件产物 +   │   │ 五条硬约束   │   │ 六套规则 +   │
│ 风险/体检     │   │ "本次参数"行 │   │ 独立于求解器 │   │ 局部交换取最优│
└─────────────┘   └─────────────┘   └─────────────┘   └─────────────┘
                         ▲                                   │

网页版：index.html --POST xlsx--> app.py --调用 core--> JSON --> 四个页签
```

**两条铁律**（写进设计，不随实现变化）：
1. **校验器不由 AI 生成或判断**，它是普通代码，只认约束和算术；每次出结果必跑，0 违反才放行。
2. **中间三步（清洗 / 建实例 / 排程）不交给大模型**，AI 只在最前面理解需求、最后面解释结果。

## 四、数据字典

> 标记说明：⚠ = 本台账里**实际出现过**脏数据的列；空白 = 结构稳定、暂未发现脏值。
> "必填"指排程必需；缺了不能排，只能标"需客户确认"。

### 4.1 订单表（14 行数据 + 1 行标题 + 1 行注释）

| 字段 | 含义 | 类型 | 必填 | 脏数据风险（本台账实测） |
|---|---|---|---|---|
| 单号 | 订单唯一标识 | 文本 | 是 | ⚠ **三种写法**：`HD-2026-101` / `HD2026102` / `104`（纯数字缺前缀）；⚠ **重复**：`HD-2026-106` 出现两次（25 件 + 40 件"第二轮追加"），不拆分会直接违反"不重不漏" |
| 客户 | 下单客户 | 文本 | 是 | 无异常，4 家客户取值稳定 |
| 接单日期 | 收到订单的日期 | 日期 | 是 | ⚠ **三种格式**：`2026/11/3` / `2026-11-03` / `2026.11.4`；⚠ **空白**（`HD-2026-109`），空白影响"尽快"类的推算基准 |
| 交期 | 客户要求的完工日 | 日期 | 是 | ⚠ **这一列是人话不是日期**：`2026-11-10` / `11月12日` / 空白 / `尽快` / `月底前`。**最高风险列**，解析错一单，风险清单整篇失真 |
| 产品 | 产品族 | 枚举 | 是 | 无异常，5 个取值均能在工艺路线表命中 |
| 数量 | 订单件数 | 整数 | 是 | ⚠ **空白**（`HD-2026-110`，备注"数量等客户确认"）。不能自己填数，否则等于替客户签字 |
| 备注 | 自由说明 | 文本 | 否 | ⚠ **口头规则藏在这里**：`急单/客户催/越早越好`（优先级）、`材料 11 月 8 日才到`（最早开工日）、`先做一半`（数量减半）、`和第二批一起做`（合并批次）。不做关键词识别就会漏约束 |

### 4.2 设备表（12 条记录：11 台本厂 + 1 台外协）

| 字段 | 含义 | 类型 | 必填 | 脏数据风险（本台账实测） |
|---|---|---|---|---|
| 设备号 | 本厂设备编号 | 文本 | 是 | ⚠ **空白**（热处理炉那行没有设备号），按"设备号为空 = 非本厂资产"处理，不报错 |
| 编号 | 车间机台编号 | 枚举 | 是 | ⚠ 工艺路线里引用的是**这一列**（`LAT` / `CNC-03`），不是设备号。两套编号混用是排错机台的头号原因 |
| 型号 | 机床型号 | 文本 | 否 | 无异常，仅用于展示，不参与计算 |
| 可做工序 | 该机能干的工序 | 枚举列表 | 是 | ⚠ **一台能干多道**（`铣、镗`），拆分时不能只取第一个；工序名要与工艺路线对齐（`攻丝` ≠ `钻`） |
| 每日班次 | 一天开几个班 | 整数 | 是 | ⚠ **不一致**：`LAT-03` 是 **3 班**，其余 2 班。一律按 16h 算会把产能算少 1/3，直接影响交期结论 |
| 状态 | 当前可用状态 | 枚举 | 是 | ⚠ **三种非"在用"**：`停机维修（11/8 起）`（CNC-03）、`闲置`（GRD-02）、`外协，不计本厂`（HT-01）。停机机台必须剔除，否则排出来就是撞机 |

### 4.3 工艺路线表（5 个产品）

| 字段 | 含义 | 类型 | 必填 | 脏数据风险（本台账实测） |
|---|---|---|---|---|
| 产品 | 产品族 | 枚举 | 是 | 与订单表"产品"列必须能对上，对不上则该单无法展开工序 |
| 工序1 ~ 工序5 | 工序名（机台）+ 单件分钟 | 文本 | 至少 1 道 | ⚠ **工序是文本**：`下料（SAW-01）20` 要拆成「工序 / 机台或机台组 / 分钟」三段；⚠ **机台写法两种含义**：`车（LAT）`= 三台任选，`铣（CNC-03）`= 点名一台，不能同等对待；⚠ **工序数不等**：阀体A 5 道、阀体B 4 道、阀芯C 只有 2 道，不能按 5 道硬套 |
| 单件工时合计 | 各工序分钟之和 | 数值 | 否 | ⚠ **校验用，不参与计算**。计算必须逐道工序累加；合计只用来抓"工序被漏解析"（解析出的分钟之和 ≠ 合计即报警） |
| 备注 | 工艺口头规则 | 文本 | 否 | ⚠ `铣削目前指定 CNC-03`（与停机冲突，见假设 A4）、`磨是瓶颈，别排太散`（需客户确认口径） |

**跨表约束**：订单.产品 → 工艺路线.产品（必须命中）；工艺路线.机台 → 设备.编号（必须存在）；设备.编号 与 设备.设备号 是两套编号，**代码里只用"编号"**。

## 五、接口定义

三个接口，网页版前端只调这三个。

### 5.1 `POST /api/plan` — 上传台账并生成排程

| 项 | 内容 |
|---|---|
| 请求 | `multipart/form-data`：`file`=xlsx 二进制；`start_date`=起始日（可空，默认"现在之后第一个可开工时刻"）；`allow_switch`=`true/false`（是否允许同组换机台） |
| 成功 | `200`，见下方 JSON |
| 失败 | `400` 文件不是 xlsx / 缺 sheet / 空表 / 某道工序找不到机台，`detail` 为中文提示 |

```json
{
  "job_id": "20261105-152904-778a",
  "params": "起始 2026-11-05 15:29 ｜ 每班 8h，班制 2 班、3 班 ｜ … ｜ 目标 迟到单数→迟到天数→总完工 ｜ …",
  "rule": "SPT+局部交换(39)",
  "start": "2026-11-05 15:29",
  "finish": "2026-11-20 17:29",
  "metrics": [{"k": "迟到订单", "v": 0, "u": "单", "s": "另 2 单交期物理不可能", "tone": "bad"}],
  "summary": {"orders": 14, "planned": 14, "tasks": 51, "violations": 0, "issues": 23},
  "schedule": [{"machine": "SAW-01", "order": "HD-2026-101", "op": "下料", "qty": 40,
                "start": "11-09 08:00", "end": "11-09 21:20", "minutes": 800, "product": "阀体A"}],
  "gantt": {"machines": [{"name": "CNC-01", "load": 42,
             "bars": [{"order": "HD-2026-101", "op": "铣", "qty": 40, "product": "阀体A",
                       "left": 1.2, "width": 3.4, "tip": "HD-2026-101 · 铣 · 40件 · …"}]}],
            "days": [{"label": "11-05", "left": 0}]},
  "risks": [{"order": "HD-2026-102", "due": "2026-11-12", "lb": "11-17 19:29",
             "eta": "11-19 22:20", "gap": -7.2, "machine": "GRD-01", "op": "磨",
             "status": "不可行", "note": "独占最快机台、零排队也要 …", "infeasible": true}],
  "issues": [{"category": "交期口径", "where": "订单!D5", "symptom": "原文「尽快」不是日期",
              "action": "按口径折算为 2026-11-09", "need_confirm": true}],
  "violations": [],
  "downloads": [{"kind": "schedule", "name": "排单表.xlsx", "url": "/api/download/20261105-152904-778a/schedule"}]
}
```

**`risks[].status` 五种取值**：`不可行`（交期下界已超过交期，改期/外协才行）/ `迟到`（排得不好，可优化）/
`临界`（余量 < 1 天）/ `按期` / `需确认`（交期是文字或空白）/ `未排产`（数据不全，未进排程）。

`risks[].lb` 是交期下界（独占最快机台、零排队的最早完工），`infeasible` 等价于 `status == "不可行"`。

### 5.2 `GET /api/result/{job_id}` — 取回结果（刷新页面后重取）

返回体与 5.1 成功响应相同（`job_id` 之后的全部字段）。`404` 表示任务已过期（本地服务只保留最近 5 次）。

### 5.3 `GET /api/download/{job_id}/{kind}` — 下载产物

| 项 | 内容 |
|---|---|
| `kind` | `schedule`（排单表 xlsx）/ `gantt`（甘特图 html）/ `risk`（风险清单 md）/ `checkup`（体检报告 md） |
| 响应 | 文件流，`Content-Disposition: attachment; filename*=UTF-8''<URL编码中文名>`（中文名不乱码） |
| 失败 | `404` 文件不存在 |

## 六、假设与边界

| # | 假设 | 边界（不成立会怎样） |
|---|---|---|
| A1 | 每道工序的"单件工时"是稳定值，直接用台账数字 | 若实际有波动或新人操作更慢，**排程偏乐观，交期风险被低估**，需按实际倍率重算 |
| A2 | 一天内机器连续可用，不建模班次交接与休息损耗 | 若两班之间有 30 分钟交接停机，**每台机每天少 0.5h 产能，一周累计约 1 个班次**，交期可能整单推迟一天 |
| A3 | 不建模换型（换产品）时间 | 若同一机台在阀体A 与阀芯C 之间换型需 40 分钟，**本排程缺这部分时间，实际完工比预测晚** |
| A4 | CNC-03 从 11/8 起停机，恢复日未知，**整周按不可用处理**；工艺里"铣（CNC-03）"的活改走 CNC-01/02 | 若 CNC-03 中途恢复，**本排程浪费了 1/3 铣削产能**，交期可提前；若客户坚持只认 CNC-03，**阀体A 全部无法开工** |
| A5 | 同组机台能力等价（LAT-01/02/03 视为可互换，CNC-01/02 视为可互换） | 若某台精度等级不够、只能干粗活，**排到那台的活实际做不了，等于撞机**，需按机台能力重新分派 |
| A6 | 热处理外协不计本厂产能，且视为**零前置延时**（前道完即可转下道） | 若外协实际需 3 天往返，**涉及热处理的单交期整体推迟 3 天**，风险清单需重排 |
| A7 | 物料按备注"到料日"可用；备注没写视为已到料 | 若实际未到料，**该单实际无法开工，排程里却已占用机台**，挤掉其他单的产能 |
| A8 | 数量空白的单**不排产**（标需客户确认），不替客户猜数量 | 若强行给个数量，**等于替客户签了交期承诺**；代价是这类单不出现在排单表里，可能被误以为"忘了" |
| A9 | 一批订单的数量一次做完，不拆批；备注"先做一半"按一半数量算 | 若允许拆批穿插，**交期可提前但排程复杂度上升**；当前实现拿不到这个收益 |
| A10 | 停机只有"整周可用 / 整周不可用"两档，**不建模按日期的停机区间** | 台账写「11/8 起停机」，指的是从 11/8 往后不可用、**此前仍可用**；但当前实现把整台机整窗口拉黑。实测：起始日设 11-02 时，若允许修前可用，总完工可由 11-18 18:20 提前到 **11-17 19:20（省 23 小时）**；默认窗口（11/09 起）因整段落在停机期内，**结论不变**。客户若需中途停机/有限期维修，需升级为按日期的可用区间（已列入待办，本期不做） |

> A4 + A10 合起来是本期最容易被客户挑战的一点：**这台机器一台活没干，到底是真停了，还是工具不会排？** 现在的答案是前者（默认窗口下确实整段停机）。为避免误解，体检报告会明确写「CNC-03 状态 停机维修（11/8 起）→ 不进入可用机台池」，让客户看得见判定依据。

## 七、验收标准

> 全部可执行、可复现，第三方照此逐条测即可。

| # | 验收项 | 通过判据 |
|---|---|---|
| V1 | **校验器 0 违反** | 用 `data/宏达精密_订单台账.xlsx` 跑一次，`checker` 四项（不重不漏 / 机台对 / 不倒序 / 不重叠）返回值全为 0；人为造一个撞机，能被抓出来并指出机台与两道单号 |
| V2 | **工时单位正确** | 抽 `HD-2026-101`（阀体A × 40 件）手算：180 分钟/件 × 40 = **7200 分钟**，程序输出的该单各工序分钟之和必须等于 7200 |
| V3 | **风险清单可追溯** | 随机抽 2 条风险，每条都能报出「单号 + 卡在哪台机 + 卡在哪道工序 + 差几天」，且在排单表里能定位到同一单的同一道工序 |
| V4 | **换数据能跑** | 把台账数量改 1 处、删 2 行、把某单交期改成文字"下周",重新运行仍出全部四件产物，且 V1 依然 0 违反、结果数字发生变化 |
| V5 | **体检报告够用** | ≥8 类脏数据，其中标"需客户确认"的 ≥3 类；每条都含"位置 / 现象 / 处理方式"，不含"可能有误差"这类不落地的描述 |
